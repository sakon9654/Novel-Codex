# การควบคุมเหตุการณ์ ความรู้ และความลับ

แนวทางลงมือทำของ `story-continuity` สำหรับเรื่องที่เก็บข้อมูลใน Obsidian

## อ่านโน้ตอย่างมีหลักฐาน

อย่าถือว่าเจอไฟล์แล้วเท่ากับอ่านแล้ว ก่อนร่าง:

1. เปิดเนื้อหาเต็มของโน้ตที่ลิงก์จาก Home/Chapter ไม่อาศัยชื่อไฟล์หรือ excerpt
2. เปิดบทต้นทางเมื่อโน้ตสรุปไม่พอสำหรับเวลา ลำดับ การใช้คำพูด หรือความลับ
3. บันทึกรายการ `Source notes read` ใน continuity brief ด้วย wikilinks
4. ดึงข้อเท็จจริงที่จำเป็นเป็นข้อความสั้นและระบุสถานะ ไม่คัดลอกข้อมูลทั้ง vault เข้ามาใน brief
5. เมื่อข้อมูลไม่ตรงกัน ให้เทียบกับฉบับต้นฉบับล่าสุดและบันทึก conflict; อย่าตัดสินจากโน้ตที่ใหม่กว่าอย่างเดียว

## โมเดลเหตุการณ์

เหตุการณ์แต่ละรายการควรตอบ:

- **เวลาเกิด:** วันที่/ช่วง/ลำดับในโลกเรื่อง หรือ `ยังไม่แน่ชัด`
- **เวลาที่เล่า/เปิดเผย:** บทและจุดที่ผู้อ่านได้รับข้อมูล
- **ก่อนหน้า/ถัดไป:** dependency ที่จำเป็นและผลสืบเนื่อง
- **ผู้เกี่ยวข้อง:** ผู้กระทำ ผู้เห็น ผู้ได้รับผล
- **ความรู้หลังเหตุการณ์:** ใครรู้อะไรจากการเห็น ได้ยิน อ่าน อนุมาน หรือถูกบอก
- **สถานะข้อมูล:** ยืนยัน, ข่าวลือ, เข้าใจผิด, ข้อสงสัย, ปกปิด, ถูกหักล้าง
- **แหล่งยืนยัน:** chapter/scene note

อย่ารวม `story chronology` กับ `reveal chronology` เป็นรายการเดียว เพราะ flashback และการสืบสวนจะทำให้สองลำดับนี้ต่างกัน

## Knowledge state ต่อคน

สำหรับทุกตัวละครสำคัญในฉาก จัดข้อมูลที่เกี่ยวข้องลงหนึ่งในสถานะต่อไปนี้:

| สถานะ | ความหมาย | ใช้เขียนได้อย่างไร |
|---|---|---|
| รู้ | ได้รับข้อมูลจากหลักฐาน/ผู้บอกและยอมรับว่าเป็นจริง | พูด คิด หรือตัดสินใจโดยใช้ข้อมูลนั้นได้ |
| เชื่อ | ยึดถือเป็นจริง แต่เรื่องยังไม่ยืนยันหรืออาจผิด | เขียนเป็นความเชื่อ ห้าม narrator รับรองแทน |
| สงสัย | มีเบาะแสแต่ยังสรุปไม่ได้ | ตั้งคำถามหรือสืบต่อได้ ห้ามใช้เป็นข้อเท็จจริง |
| เข้าใจผิด | มีข้อมูลแต่ตีความผิด | ใช้ขับพฤติกรรมได้จนกว่าจะได้รับการแก้ไข |
| ไม่รู้ | ยังไม่มีทางรับข้อมูลตาม timeline | ห้ามอ้างถึงหรือทำปฏิกิริยาราวกับรู้ |
| ซ่อน/ปฏิเสธ | รู้หรือสงสัยแต่ตั้งใจไม่พูด/ไม่ยอมรับ | บทพูดและการกระทำต้องสะท้อนการปกปิดโดยไม่เฉลยเกิน POV |

ทุกการเปลี่ยนสถานะต้องมี `เมื่อไร`, `ได้จากทางไหน`, และ source event

## Secret ledger

สร้างหนึ่ง secret note ต่อความลับสำคัญ ไม่ซ่อนความลับไว้ใน character bio อย่างเดียว:

- ความจริงที่ผู้เขียน/ระบบ canon ยืนยัน
- คนที่รู้ความจริงและแหล่งที่ได้รู้
- คนที่รู้เพียงบางส่วน/สงสัย/เข้าใจผิด
- คนหรือกลุ่มที่ยังไม่รู้
- เบาะแสที่เผยแก่ตัวละครและผู้อ่าน แยกกัน
- สิ่งที่ห้ามยืนยันใน POV/narration ก่อนถึงเวลา
- ช่วงหรือเงื่อนไขเปิดเผยที่วางไว้
- ผลต่อพล็อตและความสัมพันธ์หลังเปิดเผย
- source notes และสถานะ: `concealed`, `hinted`, `suspected`, `revealed`, `resolved`

ถ้าผู้เขียนยังไม่กำหนดความจริง ให้บันทึกเป็น `ยังไม่ล็อก` พร้อมทางเลือก ห้ามเขียนหนึ่งทางเลือกเป็น canon โดยไม่แจ้ง

## Reader reveal control

แยกข้อมูลสี่ชั้น:

1. **ความจริงเบื้องหลัง** — สิ่งที่เกิดขึ้นจริงในโลกเรื่อง
2. **ข้อมูลที่ตัวละครรู้** — จำกัดเป็นรายคนและเปลี่ยนตามเหตุการณ์
3. **หลักฐานที่ผู้อ่านเห็น** — สิ่งที่ข้อความแสดงอย่างชัดเจน
4. **ข้อสรุปที่ผู้อ่านน่าจะอนุมาน** — ระดับการชี้นำที่ผู้เขียนตั้งใจ

ก่อนส่งฉาก ให้ตรวจการรั่วโดยถาม:

- POV มีสิทธิ์รู้ความจริงนี้หรือไม่
- คำเปรียบ คำบรรยาย หรือปฏิกิริยาเผลอยืนยันตัวผู้กระทำ/แรงจูงใจหรือไม่
- การเรียกชื่อ ตำแหน่ง การสรรพนาม หรือการข้ามรายละเอียดเผยตัวตนก่อนกำหนดหรือไม่
- ฉาก recap หรือบทสนทนาพูดเกินกว่าผู้อ่านควรรู้หรือไม่
- เบาะแสนี้ชี้ได้กี่คำตอบ และตรงกับระดับความสงสัยตามแผนหรือไม่

ความคลุมเครือที่ตั้งใจควรมีขอบเขต: ผู้เขียนรู้ความจริงหรือรู้ว่าความจริงยังไม่ถูกล็อก แม้ผู้อ่านยังไม่รู้

## Continuity brief ต่อฉาก

```markdown
# Continuity Brief - Chapter NN / Scene NN
- Sources read: [[Chapter NN-1]], [[Event - ...]], [[Character A]], [[Secret - ...]]
- Story time: วันที่/เวลา; ผ่านจากฉากก่อน ...
- POV: ...; รับรู้ได้จาก ...; ห้ามรู้ ...
- Entry state: ตำแหน่ง/บาดแผล/ของสำคัญ/อารมณ์
- Character knowledge: A รู้...; เชื่อ...; ยังไม่รู้... / B ...
- Secret guard: ห้ามเฉลย...; clue ที่อนุญาตให้เห็น...
- Required event/change: ...
- Exit state: ...
- Unresolved canon: ...
```

ถ้าเขียนหลายฉากในบท ให้สร้าง brief แยกต่อฉากเมื่อเวลา, POV, ผู้รู้ หรือจุดเปิดเผยเปลี่ยน
